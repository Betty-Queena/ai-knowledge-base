# 文本向量化与 RAG 检索

## embedding 是什么

embedding 模型把一段文本映射成一个固定长度的稠密向量，
语义相近的文本，向量在高维空间里的方向也相近。
向量的长度就是维度，常见的有 384、768、1024、1536 等，
维度和模型绑定：换了模型，维度往往就变了，旧向量也无法继续使用。

衡量两个向量有多像，最常用的是余弦相似度：
两个向量的点积除以它们各自模长的乘积。
它的取值范围是 -1 到 1，只看向量方向、忽略长度，
所以不受文本长短导致的模长差异影响。取值为 1 表示方向完全一致。
需要注意，余弦相似度只有在同一个模型产出的向量之间比较才有意义，
跨模型比较得到的数字没有任何解释价值。

## 检索：暴力扫描还是近似索引

向量检索就是给定查询向量，在库里找出最相似的 Top-K。
数据量小的时候，最直接的做法是把库里所有向量读出来，逐个算相似度再排序，
这种方式结果精确、没有额外参数，缺点是耗时随数据量线性增长。
数据量到了百万级，就需要近似最近邻（ANN）索引，
例如 HNSW、IVF 这类结构，用少量精度换取大幅提速。
选择哪种取决于规模：在几千条量级上引入 ANN，
只会把"检索效果的变化"和"索引参数的调整"两件事混在一起，反而更难判断问题出在哪。

## RAG 的完整链路

检索增强生成的基本流程是：
把文档切分成若干块，对每块生成 embedding 并存入向量库；
用户提问时，先把问题同样向量化，检索出最相似的 Top-K 块，
把它们拼进提示词作为上下文，再交给大模型生成回答。
这样做的目的是让模型基于给定的资料回答，而不是凭记忆编造。

## 切块参数怎么权衡

chunkSize 指的是每块的最大字符数，overlap 是相邻块之间重叠的部分。
块切得太小，一段完整的意思可能被拆散，检索到的片段缺少上下文；
块切得太大，一块里混进多个主题，向量被"稀释"，反而不容易和问题对上，
而且拼进提示词时也会更快占满模型的上下文窗口。
overlap 的作用是缓解答案正好落在切分边界上的情况：
有重叠时，跨边界的内容至少能在其中一块里保持完整。
常见的朴素做法是按固定字符数滑窗切分，它不识别句子和段落边界，
实现简单但可能把一句话截断，这是后续要改进的地方。

## 相似度阈值

有些实现会先按一个最低相似度阈值过滤，再取 Top-K。
阈值的作用是给"没有相关内容"这种情况留一条退路：
如果所有结果都低于阈值，就当作检索不到，直接拒答，而不是硬塞给模型。
但阈值定得太高会把本来能答的问题也挡掉，
因此它必须用带标注的评测集校准，而不是凭经验拍一个数。
衡量检索质量的常用指标有命中率（HitRate@K）和平均倒数排名（MRR@K）：
前者看前 K 条里有没有正确答案所在的文档，后者还额外关心它排在第几位。
