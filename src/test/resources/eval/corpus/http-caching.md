# HTTP 缓存：强缓存与协商缓存

浏览器拿到一份响应之后能不能直接复用，取决于响应头里怎么描述它的新鲜度和校验方式。
按"要不要再问一次服务器"来划分，可以分成强缓存和协商缓存两类。

## 强缓存：干脆不发请求

强缓存命中时，浏览器直接用本地副本，连请求都不会发出。
控制它的响应头主要是 `Cache-Control`：

- `max-age=3600`：从响应生成算起 3600 秒内都算新鲜；
- `s-maxage`：只对共享缓存（CDN、反向代理）生效，会覆盖 `max-age`；
- `private`：只允许浏览器这类私有缓存保存，CDN 不能存；
- `public`：允许任何缓存保存，包括共享缓存；
- `immutable`：告诉浏览器在这一轮有效期内不必再发校验请求，刷新页面也不例外；
- `no-store`：完全不保存，任何缓存都不得落盘；
- `no-cache`：可以保存，但每次使用前都必须回源校验。

这里最容易混淆的是 `no-cache` 和 `no-store`：前者是"可以存，但每次都要问"，
后者是"根本不许存"。名字里的 no-cache 并不是"不缓存"的意思。

另外还有一个历史上更早的头部 `Expires`，它给的是一个绝对时间点，
依赖客户端与服务端的时钟一致，现在通常只作为 `Cache-Control` 缺失时的兜底。

## 协商缓存：发请求但可能不带响应体

强缓存过期之后，浏览器会带着校验字段再问一次服务器，由服务器决定是返回新内容还是告诉它"没变"。

- `ETag` / `If-None-Match`：ETag 是服务器给某个版本内容的标识，
  浏览器下次把它放进 `If-None-Match` 发回去；服务端比对后如果内容没变，返回 304，
  响应里不带响应体，只带头部。
- `Last-Modified` / `If-Modified-Since`：按最后修改时间来校验。
  它的精度只到秒，而且如果文件在极短时间内被改了两次、或者只是被重新写了一遍而内容没变，
  这两种情况都可能判断失准，所以优先级低于 ETag。

ETag 又分强校验和弱校验，弱校验的 ETag 以 `W/` 开头，
表示语义等价即可，不要求逐字节相同。

## 304 到底省了什么

304 响应没有响应体，省下的是传输内容的流量和时间，
但请求本身仍然发出去了，一次往返的网络延迟省不掉。
所以对几乎不变的静态资源（带内容哈希命名的 JS、CSS、字体文件），
更适合用 `max-age` 配一个很长的有效期，让强缓存直接命中。

## Vary 与缓存键

`Vary` 用来告诉缓存：同一份 URL 的响应会随某些请求头而变化。
例如 `Vary: Accept-Encoding` 表示压缩版和未压缩版要分开缓存，
`Vary: Accept-Language` 表示不同语言要分开缓存。
如果不写 Vary 而响应又确实依赖某个请求头，就可能把错误的版本发给别人。

缓存可以存在于多个层级：浏览器本地缓存、CDN 边缘节点、反向代理（如 Nginx）、
以及应用内部的缓存。每一层都可能独立决定是否复用，排查"为什么改了代码页面还是旧的"时，
需要把这些层逐一看过去。
